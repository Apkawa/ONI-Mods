## R1: mod structure

Source: subagent report (files verified in `BuildDoorOverWall/Mod.cs`, 622 lines).

- **Single source file** `BuildDoorOverWall/Mod.cs`: `UserMod2.OnLoad` + 4 programmatic Harmony postfixes + static helpers (`FindMethod`, `IsDoorDef`, `IsReplacementPlacementPossible`). **No mod UI at all** — the mod patches the game's native build tool; user drags a door from the vanilla build menu over a wall.
- `UtilLibs` carries PLib 4.19.0 (only `PUtil.LogDebug` / `.F()` used — no PLib UI).
- **Flow:** `Mod.OnLoad` patches `Assets.AddBuildingDef(BuildingDef)` (postfix `Assets_AddBuildingDef_DoorReplacement__Patch`): for every door def sets `ReplacementLayer = ObjectLayer.ReplacementTile`, `ReplacementCandidateLayers = { FoundationTile, Backwall }`, `ReplacementTags = { FloorTiles, Backwall, Ladders }` (idempotent). Then the game's native "build over replaceable tile" path does placement; `Constructable.FinishConstruction` destroys the wall and returns items.
- Other 3 postfixes: `BuildingDef.IsValidPlaceLocation` (4-arg, cosmetic hover-card fix), `BuildingDef.IsValidReplaceLocation` (cosmetic), private `BuildTool.TryBuild(int)` (functional: non-anchor cell of the 1×2 door sits on the wall — replicates native fallback over the door area, creates plan via `def.TryReplaceTile(...)` and stores at `Grid.Objects[anchorCell, (int)def.ReplacementLayer]`; mirrors orientation: Neutral→R180 + anchor moved up, R90→R270 + anchor moved right).
- Shared gate `IsReplacementPlacementPossible(def, go, cell, orientation)`: door-def scope check → `def.RunOnArea` → `GetReplacementCandidate` → `Replaceable`/`CanReplace` → `IsReplacementLayerOccupied` → 6-arg `def.IsValidPlaceLocation(..., replace_tile: true, restrictToActiveWorld: false)`.
- **`IsDoorDef(BuildingDef)`** (Mod.cs:226-240): door iff `BuildingComplete` prefab has `CopyBuildingSettings.copyGroupTag == GameTags.Door` OR a `Door` component. No shared door tag / BuildCategories exists (Doors menu is hardcoded static lists in `BuildMenu.cs:151-159` / `TUNING/BUILDINGS.cs:687-709`).
- Game APIs used: `Grid.PosToCell`, `Grid.Objects[cell,layer]` (read+write), `Grid.CellAbove/CellRight/CellToPosCBC`, `def.RunOnArea`, `def.GetReplacementCandidate`, `def.CanReplace`, `def.IsReplacementLayerOccupied`, `def.IsValidPlaceLocation` (6-arg), `def.TryReplaceTile(visualizer, pos, orientation, selected, facadeID)`; components: `CopyBuildingSettings`, `Door`, `PrimaryElement`, `LogicPorts`, `Prioritizable`; mode checks: `DebugHandler.InstantBuildMode`, `Game.Instance.SandboxModeActive`.
- **TryBuild postfix bails in instant-build/sandbox** (Mod.cs:456-464, "Stage 3, deferred"); README known issues: does not work in sandbox; door top end in a wall mirrors AirLock orientation.
- Open (not answerable from code): door-over-door replacement behavior at runtime (candidate layers not restricted to walls-only; `CanReplace`/tags decide); save compatibility of queued plans.

## R2: game door buildables

No door-to-door replacement/upgrade mechanism exists in the base game.
- **Tags:** prefab tag = auto per-PrefabID tag (BuildingConfigManager.cs:74-75); `GameTags.Door` is only used as copyGroupTag, never added to door prefabs; no tag distinguishes pressure vs internal doors.
- Needs runtime check: none blocking — the decompilation is of the installed game (decompiled from ~/ONI/dlls).

## R5: Bug A root cause — wall-over-door plan cancelled at construction time ("Место не подходит для стройки")

Source: orchestrator verification in `lib_sources/Assembly-CSharp/` (after user test report, 2026-09-15 evening).

- **The failing check:** `Constructable.cs:747` (in the build-state update, when digs are done and items fetched, before the build chore runs):
  `bool flag = building.Def.IsValidBuildLocation(base.gameObject, base.transform.GetPosition(), building.Orientation, IsReplacementTile);`
  On failure the plan gets the "InvalidBuildingLocation" status / "Место не подходит для стройки" and the build chore is never created.
- **Funnel:** the 4-arg Vector3 overload (`BuildingDef.cs:1209`) → 5-arg Vector3 (`:1214`) → **core int overload** `IsValidBuildLocation(GameObject source_go, int cell, Orientation orientation, bool replace_tile, out string fail_reason)` (`:1220`). Patching the int overload covers both callers.
- **Core overload body (`:1220-1341`):** `Grid.IsValidBuildingCell` + `IsAreaValid` (cell offsets/world only, no occupancy), then a `switch (BuildLocationRule)`:
  - `NotInTiles` (wall-like defs): `flag = (replace_tile || Grid.Objects[cell,9] == null || Grid.Objects[cell,9] == source_go) && !Grid.HasDoor[cell];` — **`!Grid.HasDoor[cell]` blocks even with `replace_tile == true`** → this is the Bug A block (wall plan over a door cell). The rest of the branch (own Backwall-layer occupant check) passes for a door cell (no backwall there).
  - `Tile` (door + floor-tile defs): `flag = true`, then only layer-27 (wire with NotInTiles def → false) and layer-2 (backwall with NotInTiles def → `flag = replace_tile`) checks. **NO HasDoor check** → door-over-door and tile-over-door pass the construction re-check natively (consistent with the user's door-over-door run reaching the construction phase).
  - tail: `flag && ArePowerPortsInValidPositions(...) && AreConduitPortsInValidPositions(...)` (walls/tiles have no ports → true).
- **`IsReplacementTile` on our plans:** `TryReplaceTile` (`BuildingDef.cs:490`) sets `component.IsReplacementTile = true` on the prefab's Constructable before `KInstantiate` and resets it after — the clone keeps `true`, so the re-check and the `OnCompleteWork` anchor branch both see `IsReplacementTile == true`.
- **Plan grid registration:** `Constructable.MarkArea` (`Constructable.cs:441-458`): `layer = IsReplacementTile ? def.ReplacementLayer : def.ObjectLayer` — i.e. **the plan itself sits in `Grid.Objects[cell, (int)def.ReplacementLayer]`** (ReplacementBackwall for wall plans, ReplacementTile for door/tile plans) at every cell of its area (plus `IsTilePiece` extra tile-layer registration + `Grid.IsTileUnderConstruction`). Consequence: the shared gate `IsReplacementPlacementPossible`'s `def.IsReplacementLayerOccupied(cell)` check (no source_go exclusion — native `BuildingDef.cs:305-322` checks `Grid.Objects[cell, ReplacementLayer] != null` only) **sees the plan itself and returns occupied → the flip cannot fire at construction time**. The gate's occupancy check must exclude `source_go`.
- **All `IsValidBuildLocation` callers (grep, Assembly-CSharp):** `BaseUtilityBuildTool.cs:415/437/473` (utility hover tint / instant-build hover — other defs), `BuildTool.cs:325` (normal hover/placement, `replace_tile` defaults false — for a wall-over-door the companion `IsValidPlaceLocation(replace_tile:false)` still fails, so flipping `IsValidBuildLocation` there changes nothing), `BuildTool.cs:379` (instant-build/sandbox branch → `InstantBuildReplace` native path; out of scope, no crash risk — in sandbox it just builds via the native replacement flow), `Constructable.cs:747` (the Bug A site). **Patching the int overload is safe for all callers.**

## R6: Bug B root cause — door-over-door construction crash (`ArgumentOutOfRangeException`)

Source: orchestrator verification (stack trace from user + code in `Constructable.cs:140-260`, `Deconstructable.cs:327-375`, `TracesExtesions.cs`, `BuildingDef.cs:324-345`).

- **Native replacement-completion flow (both directions, `Constructable`):**
  - `OnCompleteWork` (`:158-215`): when `IsReplacementTile`, `candidate = building.Def.GetReplacementCandidate(anchor_cell)`; if found: `SimCellOccupier.DestroySelf(callback → FinishConstruction)` (DEFERRED destruction), `KAnimGraphTileVisualizer.skipCleanup = true`, **`Deconstructable.SpawnItemsFromConstruction(worker)` immediately** (items returned — succeeds, the candidate is still alive), `Trigger(1606648047, ReplaceCallbackParameters)`, `candidate.DeleteObject()`; then `FinishConstruction` is NOT called directly (it is the deferred callback).
  - `FinishConstruction` (`:223-257`): called from the destruction callback; when `IsReplacementTile && PlacementOffsets.Length > 1`, `RunOnArea` over the rest of the new building's area: per cell `GetReplacementCandidate(offset_cell)` → `DestroySelf(null)` + **`SpawnItemsFromConstruction(worker)`** + `Trigger(1606648047, ...)` + `DeleteObject()`; then `UnmarkArea()` + `def.Build(...)` spawns the finished building.
- **The crash mechanism (door-over-door, new 1×2 over old 1×2, cells shared):** the old door's GO is registered in `ObjectLayers[Building(1)]` at BOTH of its cells (`MarkArea` per-cell). Anchor branch processes it at the anchor cell (deferred destroy + items spawned while alive). The deferred callback fires during the old door's own `OnCleanUp` (building-complete cleanup) — at that moment the door's grid entries are **still present** (its `UnmarkArea`/cleanup has not removed them yet; `DeleteObject` = `TracesExtesions.DeleteObject` = `Trigger(1502190696, go)` + `Object.Destroy(go)`, i.e. deferred, no immediate grid removal). The sweep then finds the SAME dying door at the other cell and calls `SpawnItemsFromConstruction` on it a second time → `PrimaryElement.get_Temperature` → `StructureTemperatureComponents.OnGetTemperature` reads a `KSplitCompactedVector` handle whose payload was already removed in `OnCleanUp` → **`ArgumentOutOfRangeException`** (game crash).
- **Guard design (chosen):** Harmony **prefix** on `Constructable.FinishConstruction(UtilityConnections, WorkerBase)` (non-public — Harmony handles private methods; the method has two args, no out params, clean prefix signature). In the prefix, when `IsReplacementTile && def.PlacementOffsets.Length > 1`: find `anchor_candidate = def.GetReplacementCandidate(anchor_cell)`; for each other cell of the area, if `GetReplacementCandidate(cell)` returns the SAME GO, that candidate was already destroyed+spawned by the anchor branch → **clear its entries from `Grid.Objects[c, (int)layer]`** (write null; native pattern — BuildTool.cs:376 writes `Grid.Objects[cell, layer] = gameObject`) for every layer in `def.ReplacementCandidateLayers` where the entry equals that GO. The native sweep then finds nothing at those cells → no double destroy/spawn → no crash. Stateless, surgical, does not touch preview paths, does not affect distinct candidates (e.g. 1×2 door over two separate 1×1 walls — different GOs — still processed natively).
- Rejected alternatives: prefix on `Deconstructable.SpawnItemsFromConstruction` (needs a destruction-state API with uncertain flag timing during `OnCleanUp`); static dedup set (state leak); patching `GetReplacementCandidate` (would poison preview-path lookups).

## R8: Bug C root cause — wall (ExteriorWall) over only the TOP cell of a 1×2 door: door → floor item blocks, ghost duplicate building

Source: subagent report (read-only trace in `lib_sources/Assembly-CSharp/` + `BuildDoorOverWall/Mod.cs`).

- **Door geometry:** Door is 1×2, offsets `{(0,0),(0,1)}` — anchor = clicked/bottom cell, top cell = anchor+(0,1) (`DoorConfig.cs:12`, `BuildingDef.cs:1795`).
- **Placement:** mod's 6-arg flip routes the 1×1 wall plan natively; plan spawned via `TryReplaceTile` with `Constructable.IsReplacementTile = true`, anchored at the clicked (top) cell; plan registers only `Grid.Objects[topCell, ReplacementBackwall]` (`Constructable.cs:375-405,441-460`).
- **THE core anomaly (native): double `FinishConstruction` for a multi-cell candidate.** `SimCellOccupier.DestroySelf(callback)` (`SimCellOccupier.cs:143-181`) adds **one callback handle per placement cell** of the candidate (door = 2 cells → 2 handles, each a deferred `SimMessages.ReplaceElement(cell, Vacuum, ..., handle.index)`); the sim step applies both replacements and releases **both** callbacks (`Game.cs:1133-1142`, `World.cs:86-90`) → **`Constructable.FinishConstruction` executes TWICE** (no reentry guard; `Constructable.cs:223-291`):
  - FC#1: `UnmarkArea` (`unmarked=true`) + `Def.Build(topCell)` → wall W1, marks `Grid.Objects[topCell, Backwall]=W1`.
  - FC#2: `UnmarkArea` no-op; **`Def.Build(topCell)` AGAIN** → wall W2 at the same cell; `MarkArea` overwrites the Backwall slot W1→W2 → **W1 is a live ghost GO** (visual + PrimaryElement + components, no grid slot; its queued element replacement overwritten by W2's).
  - Consequence: two wall GOs at one cell; cell holds one copy of the wall element mass while two GOs claim mass → mass accounting corrupted; deconstructing later could double-return items (W1's deconstruction returns items from construction data even though its cell element is owned by W2).
- **Door item return:** `Deconstructable.SpawnItemsFromConstruction(worker)` (`Constructable.cs:202-206` → `Deconstructable.cs:327-385`) spawns the door's material as **item chunks in the Ore layer at the door's cells** (400 kg chunks) + per-chunk `Trigger(580035959, worker)` — this is the game's standard "items to ground, worker picks up" path, **code-identical for wall and tile candidates** (not the differentiator).
- **1606648047 = `GameHashes.ObjectReplaced`** (`GameHashes.cs:12`); listeners: `BuildingComplete.OnObjectReplaced` (`BuildingComplete.cs:96,123-126` — sets `replacingTileLayer` → `WasReplaced()` L44-46 → OnCleanUp unmark branch), `ZoneTile.OnObjectReplacedDelegate`, `StorageTile.OnObjectReplaced`.
- **Wall-vs-tile diff (same cell, same flow):**
  1. Ghost visibility: wall renders via GO/sprite (ghost W1 visible-ish); foundation tile renders via cell/ground renderer → ghost tile visually identical (this is NOT conclusive for the user's observation — W1/W2 are at the exact same position).
  2. `ReplaceCallbackParameters.TileLayer = building.Def.TileLayer` (`Constructable.cs:208`): wall → `NumLayers` → door `WasReplaced()==false` → door's OnCleanUp **unmarks** its Building-layer slots (clean); tile → `FoundationTile` → `WasReplaced()==true` → unmark **skipped** → **stale door grid entries persist** at both door cells (latent grid corruption in the "working" tile case).
  3. Tile plan is `IsTilePiece` → extra FoundationTile mark + `Grid.IsTileUnderConstruction`; wall plan marks only ReplacementBackwall.
- **Mod patches verified non-interfering** for this scenario: TryBuild postfix door-only; FinishConstruction prefix gated on multi-cell (`PlacementOffsets.Length > 1`) — inert for 1×1 wall/tile plans; TryReplaceTile prefix bails only on same-PrefabID doors; flip postfixes only flip placement booleans.
- **Open / runtime-dependent:** (a) whether the double-FC ghost is what the user saw vs the item chunks ("натуральные блоки"); item path identical wall/tile in code, so the user-visible wall-specific difference is not fully pinned from code alone; (b) worker pickup of spawned chunks not verifiable (AIWorker/WorkerInventory missing from tree); (c) game log had no entry for the session.
- **Key implication for the fix:** the double-callback comes from the native `DestroySelf` per-cell handles; any fix must ensure `FinishConstruction` (and its `Def.Build`) runs effectively ONCE per replacement completion (or make the second run a no-op), for BOTH wall-over-door and door-over-door candidates (door-over-door has the same latent double-`Def.Build` — the Bug B crash guard only cleaned the sweep, not the double Build).

## R9: Bug D root cause — partial-overlap door-over-door: old door dismantled, new door never appears, items lost

Source: subagent report (read-only trace in `lib_sources/Assembly-CSharp/` + `BuildDoorOverWall/Mod.cs`).

## R12: Bug E root cause RESOLVED — the reverse-direction check in `TryFindReplacementCandidate` vetoes tile/backwall candidates for the airlock doors (data-driven, E-1 instrumentation)

- **Evidence (Player.log, 2026-09-15 session):** every failing hover/tint verdict for `ManualPressureDoor` is `gate hover/tint: def=ManualPressureDoor cell=... orient=Neutral => FAIL no replacement candidate in the door area` — i.e. the gate dies at the FIRST step of `TryFindReplacementCandidate` (candidate search), never reaching the occupancy check or the native 6-arg call. Separately: `TryBuild postfix: def=ManualPressureDoor cell=64055 — replacement-plan уже есть (ManualPressureDoorUnderConstruction)` — the drop DID succeed natively (plan created by the vanilla path), so the bug is cosmetic: the hover gate only.
- **Root cause:** the last step of `TryFindReplacementCandidate` (Mod.cs, "reverse-direction check", Stage 3/4) reads `if ((IsWallDef(def) || IsTileDef(def)) && (candidateComplete == null || !IsDoorDef(candidateComplete.Def))) return false;`. `IsTileDef(def)` = `BuildLocationRule.Tile && TileLayer == FoundationTile`. The four airlock doors set BOTH (`ManualPressureDoorConfig.cs:10`: `BuildLocationRule.Tile`; R11: `TileLayer = FoundationTile`) — so `IsTileDef(airlock) == true` and the check misfires on door defs: for a tile or drywall occupant in the footprint the candidate is not a door → rejected. The check was written for WALL/TILE defs ("wall/tile over door only"), never expecting a DOOR def to trip it. `Door`/`WoodenDoor` have `TileLayer = NumLayers` → `IsTileDef == false` → unaffected — exactly matching the user's observation (bug only for the four airlock doors).
- **Why the native 4-arg hover fails (the visible texts):** `IsValidPlaceLocation(..., replace_tile: false)` → `IsAreaClear` → for `BuildLocationRule.Tile` defs every footprint cell runs `IsValidTileLocation` (BuildingDef.cs:661,792): over a foundation tile the tile-layer check at :608 fails with `HELP_BUILDLOCATION_OCCUPIED` («Нужно построить на свободном участке»); over a drywall cell the `!replacement_tile` branch at :810 fails with `HELP_BUILDLOCATION_BACK_WALL` («Мешает задняя стена»). Both failures are native; the mod's gate was supposed to override them via the `replace_tile:true` 6-arg call but never got that far.
- **Why the ghost is WHITE over tiles but RED over drywall:** `BuildTool.UpdateVis` (BuildTool.cs:177) ORs the 4-arg hover result with `IsValidReplaceLocation` to pick the tint. `IsValidReplaceLocation` returns true for a legit vanilla airlock-over-tile replacement (that's also why the drop places) → white ghost over tiles; over drywall it's false → red ghost. The red TEXT in both cases comes from the 4-arg `fail_reason` because the postfix forces `__result=false`.
- **Why the drop still works (user: «двери все равно ставятся»):** the placement path (BuildTool.TryBuild → TryPlace → 6-arg, vanilla `replace_tile` semantics for foundation replacement) is NOT gated by the mod's hover postfix; the native vanilla foundation-replacement flow creates the plan, and the mod's TryBuild postfix bails early when a plan already exists (Mod.cs:883-888). The hover gate is cosmetic-only here.
- **Why the gate's native 6-arg call (replace_tile:true) PASSES for both scenes (verified in decompiled source):** `IsAreaClear` :608 — the tile-layer block is skipped when `GetReplacementCandidate(cell)` found the occupant (`gameObject != null && != source_go`); `IsValidTileLocation` :810 — the backwall block requires `!replacement_tile` → bypassed with `replace_tile:true`. So the only failing sub-check in the whole gate was the line-741 reverse-direction check.
- **Fix (E-3, data-driven):** skip the reverse-direction check for door defs: `if (!IsDoorDef(def) && (IsWallDef(def) || IsTileDef(def)) && (candidateComplete == null || !IsDoorDef(candidateComplete.Def)))`. Non-door wall/tile defs (wall-over-door Stage 3/4, tile-over-door) keep the check unchanged; door defs (all six, including the four airlocks) may now have tile/backwall/door candidates — the gate then validates them via the native 6-arg `replace_tile:true` call, which is exactly the drop-path validation (R11 fix-design item 3). The 6-arg IsValidPlaceLocation postfix is wall-defs-only (`IsWallDef` guard) and is unaffected.
- **Expected re-test (RU):** ManualPressure/Pressure/Insulated/Bunker hover over bare tile AND over drywall → white preview, no red tooltip; placement as before. Log should show `gate hover/tint: def=... => PASS` for those drags.
