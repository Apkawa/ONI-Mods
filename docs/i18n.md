# Шпаргалка по i18n в Oxygen Not Included

Как устроена локализация в игре и как перевести/переворачивать строки в модах.
Актуально по декомпилированному коду игры (`lib_sources/Assembly-CSharp/`).

**Источники в `lib_sources/`:**

| Файл | Что описывает |
| --- | --- |
| `Assembly-CSharp/Localization.cs` | загрузка .po, валидация переводов, языки, шрифты |
| `Assembly-CSharp/LocString.cs` | тип строки, создание ключей (`CreateLocStringKeys`), словарь `Strings` |
| `Assembly-CSharp/KMod/Mod.cs` → `LoadStrings()` | загрузка всех `*.po` из папки мода `strings/` |
| `Assembly-CSharp/LanguageOptionsScreen.cs` | язык-как-отдельный-мод (UGC), `strings.po` в корне мода |
| `Assembly-CSharp/STRINGS/*.cs` | сами строки игры (EN-оригиналы) по классам `STRINGS.*` |

Файлы игры (read-only): `~/ONI/game/OxygenNotIncluded_Data/StreamingAssets/strings/`.

---

## 1. Как устроена локализация

- Все строки игры — **статические поля типа `LocString`** в классах namespace `STRINGS`
  (декомпилировано в `lib_sources/Assembly-CSharp/STRINGS/`: `BUILDINGS.cs`, `UI.cs`, ...).
- **Ключ строки = путь по иерархии классов**: `STRINGS.<КЛАСС>.<ВЛОЖЕННЫЙ_КЛАСС>...<ПОЛЕ>`.
  Пример: `STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME` → «Wicker Door».
- При запуске `Localization.Initialize()` грузит выбранный `.po` и
  `Localization.OverloadStrings(...)` **отражением перезаписывает значения полей `LocString`**
  на переводы из `msgstr`. То есть в рантайме `STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME`
  уже содержит «Плетеная дверь», а в DLL/декомпиляции — английский оригинал.
- Параллельно строки дублируются в словарь `Strings` (`Strings.Get("STRINGS...")`) —
  программный доступ к локализации по ключу.
- Локализация тянет за собой **шрифт**: в шапке .po указывается `"Language: <code>"`,
  игра подставляет локальный шрифт (`RobotoCondensed` для `ru`) и включает RTL-режим
  для `ar`/`he`.

**Поддерживаемые коды языков** (`Localization.Locales` / `PreinstalledLanguages`):
`en` (default), `zh_klei`, `ko_klei`, `ru_klei` (preinstalled) + UGC-языки через моды.

## 2. Где лежат файлы

### Внутри игры (`~/ONI/game/OxygenNotIncluded_Data/StreamingAssets/strings/`)

| Файл | Содержимое |
| --- | --- |
| `strings_template.pot` | EN-шаблон: все ключи, `msgid` = английский текст, `msgstr` пустой |
| `strings_preinstalled_ru_klei.po` | русский (preinstalled) |
| `strings_preinstalled_zh_klei.po` / `_ko_klei` | китайский / корейский |
| `preinstalled_icon_<code>.png` | иконки языков в меню Translations |
| `polib.py`, `merge_*.bat`, `update_from_pot.py` | собственные инструменты Klei |

Загрузка preinstalled: `Localization.GetPreinstalledLocalizationFilePath(code)`
= `StreamingAssets/strings/strings_preinstalled_<code>.po`.

### Внутри мода

| Механизм | Путь | Кто грузит |
| --- | --- | --- |
| Локализация мода / правка строк игры | **`<mod>/strings/*.po`** (все .po в папке) | `Mod.LoadStrings()` при загрузке мода |
| Язык как отдельный мод (выбирается в Translations) | **`<mod>/strings.po`** (в корне контента, НЕ в `strings/`) | `LanguageOptionsScreen` при старте игры |

⚠️ **Нюанс `strings/`:** `Mod.LoadStrings()` грузит **каждый** `.po` в папке и применяет
все по очереди — если положить туда сразу `ru.po` и `en.po`, последний перечитанный файл
перекроет первый для тех же ключей. Для мультиязычности лучше брать подход Futility
(см. §5, шаг 3).

Также важно: preinstalled-переводы грузятся **до** загрузки модов, поэтому любой мод
через `<mod>/strings/*.po` может **переопределить текст игры** (в т.ч. русский).

## 3. Формат `.po`

Файл — Gettext:

```po
msgid ""
msgstr ""
"Project-Id-Version: \n"
"Language: ru\n"
"MIME-Version: 1.0\n"
"Content-Type: text/plain; charset=UTF-8\n"

#. STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME
msgctxt "STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME"
msgid "<link=\"WOODENDOOR\">Wicker Door</link>"
msgstr "<link=\"WOODENDOOR\">Плетеная дверь</link>"
```

- `msgctxt` — **ключ** (по нему игра находит поле), `msgid` — английский текст,
  `msgstr` — перевод. Игра матчит по `msgctxt` и пишет `msgstr` в поле.
- Строки могут быть многострочными (продолжение — строки, начинающиеся с `"`).
- `#, fuzzy` и служебные заголовки игра игнорирует.
- В шапке обязателен заголовок (`msgid ""` / `msgstr ""`), а для UGC-языка —
  `"Language: ru"`, иначе локаль/шрифт не применятся.

### Валидация при записи перевода

`Localization.OverloadStrings` **тихо отбрасывает** перевод (и пишет в Player.log
`TRANSLATION ERROR!`), если:

1. **Параметры** `{0}`, `{1}`, ... не совпадают 1:1 с английским текстом
   (`AreParametersPreserved`).
2. **Тегов `<link>`** больше, чем в английском, или они не сбалансированы/не вложенны
   (`HasSameOrLessLinkCountAsEnglish`, `HasMatchingLinkTags`).

То есть при переводе теги `<link="ID">` и `{N}` переносятся в `msgstr` **как есть**.

## 4. Поиск: RU-строка ↔ EN-строка ↔ класс

**RU → EN → код** (пример: «Плетеная дверь»):

```bash
S=~/ONI/game/OxygenNotIncluded_Data/StreamingAssets/strings
# 1) ключ по русскому тексту:
grep -B2 -A2 'msgstr ".*Плетеная дверь' $S/strings_preinstalled_ru_klei.po
# 2) английский msgid по ключу:
grep -A3 'msgctxt "STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME"' $S/strings_template.pot
# 3) где живёт строка в коде (class/field):
rg 'WOODENDOOR' ~/code/ONI_MODS/lib_sources/Assembly-CSharp
```

**EN → код:** сразу `rg 'Wicker Door' lib_sources/Assembly-CSharp` →
`STRINGS/BUILDINGS.cs: WOODENDOOR.NAME` → класс постройки `WoodenDoorConfig`
(`ID = "WoodenDoor"`), компонент `Door`.

Готовый ответ для примера:

| RU | EN | Ключ | Класс |
| --- | --- | --- | --- |
| Плетеная дверь | Wicker Door | `STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME` | `WoodenDoorConfig` + компонент `Door` (prefab ID `WoodenDoor`) |

## 5. Локализация своего мода

### Шаг 1. Класс строк

Строки мода объявляются статиком `LocString`. Для «родной» интеграции класс должен быть
в namespace `STRINGS` (именно этот namespace регистрирует `Localization.AddAssembly`):

```csharp
using STRINGS;

namespace STRINGS
{
    public class MYMOD
    {
        public static LocString WELCOME = "Hello from my mod!";
        public static LocString BUILDING_NAME = "My Door";
    }
}
```

### Шаг 2. Регистрация в `UserMod2.OnLoad`

```csharp
public override void OnLoad(bool first_load)
{
    base.OnLoad(first_load);
    // назначит ключи STRINGS.MYMOD.* и зарегистрирует ассамбли для OverloadStrings
    Localization.RegisterForTranslation(typeof(MYMOD));
}
```

Ключ = `STRINGS.<имя класса>.<имя поля>` (проверяется в `LocString.CreateLocStringKeys`:
поля обязаны быть `static`).

### Шаг 3. Файл перевода

Одноязычный мод — достаточно одного файла `<mod>/strings/ru.po`
(игра сама подхватит все `.po` из `strings/`):

```po
msgid ""
msgstr ""
"Language: ru\n"
"Content-Type: text/plain; charset=UTF-8\n"

#. STRINGS.MYMOD.WELCOME
msgctxt "STRINGS.MYMOD.WELCOME"
msgid "Hello from my mod!"
msgstr "Привет от моего мода!"

#. STRINGS.MYMOD.BUILDING_NAME
msgctxt "STRINGS.MYMOD.BUILDING_NAME"
msgid "My Door"
msgstr "Моя дверь"
```

Мультиязычный мод (подход Futility, `example_mods/aki-art_ONI-Mods/Futility/Loc.cs`) —
папка **`translations/`** (не `strings/`, чтобы игра не грузила всё подряд) и выбор
файла по текущей локации:

```csharp
string code = Localization.GetLocale()?.Code; // "ru", "" если english
string path = Path.Combine(ModContentPath, "translations", code + ".po");
if (File.Exists(path))
    Localization.OverloadStrings(Localization.LoadStringsFile(path, isTemplate: false));
```

### Шаг 4. Генерация шаблона (опционально)

Чтобы не писать `msgid` вручную — сгенерировать `.pot` по своим классам:

```csharp
Localization.GenerateStringsTemplate(typeof(MYMOD), "./strings_templates");
// → strings_templates/strings_template.pot с готовыми msgctxt/msgid и пустыми msgstr
```

(у Futility: `Loc.Translate(typeof(FLoc), generateTemplate: true)`).

## 6. Частые вопросы

- **Где в рантайме взять локализованную строку кодом?** `Strings.Get("STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME")`
  или само поле `STRINGS.BUILDINGS.PREFABS.WOODENDOOR.NAME` (после загрузки перевода).
- **Мод может менять перевод игры?** Да: положите в `<mod>/strings/*.po` запись с ключом
  строки игры — `OverloadStrings` перетишет preinstalled-перевод.
- **Почему мой перевод не подхватился?** Проверьте в Player.log `TRANSLATION ERROR!`
  (несоответствующие `{N}`/`<link>`), точное совпадение `msgctxt` (регистр, точки)
  и что файл лежит в `<mod>/strings/`.
- **Язык-мод (UGC)?** Отдельный мод с `strings.po` **в корне** контента
  (`LanguageOptionsScreen.GetLanguageFilename`), работает только с распакованным
  (directory) контентом и выбирается в меню Translations.
- **Почему шрифт «ломается» в моде?** Если в шапке .po нет `"Language: ru"`,
  `Localization.GetLocale` не установит локаль и шрифт останется дефолтным.
