# 2026-09-22_drywall-sticky-selection-frame: BestBuildDryWall — белая рамка выделения застревает на курсоре

**Created:** 2026-09-22T11:22:01+03:00

## Scope

**In scope:**
- Косметический баг мода BestBuildDryWall: белая рамка выделения застревает в размерах и прилипает к курсору после отпускания ЛКМ, если шифт был отпущен раньше ЛКМ.
  - Случай 1: ЛКМ нажат → шифт отпущен → ЛКМ отпущен. Призраки исчезают, план не создаётся (ок), рамка остаётся — баг.
  - Случай 2: протяжка с шифтом → шифт отпущен → протяжка продолжается с зажатым ЛКМ → рамка застревает — баг. Рамка должна исчезать **в момент отпускания шифта** (в середине тяжки, пока ЛКМ удерживается), а не только при отпускании ЛКМ.
- Рамка должна убираться при отпускании ЛКМ (случай 1 — исправлено в Stage 1).
- Поведение «отпустил шифт → снова нажал шифт без движения мыши → продолжил тянуть» сейчас корректное — не ломать (исправление не должно его ломать): при повторном зажатии шифта во время тяжки рамка должна снова появляться.

**Out of scope:**
- Побочный эффект в случае 2: после отпускания шифта vanilla `OnMouseMove` уходит в Brush-ветку и вызывает `AddDragPoints` (кисть начинает ставить блоки при протяжке). Общая логика по оценке пользователя корректная — не трогаем.
- Изменение логики создания плана, призраков, GetMode-переключения.
- Любые другие моды.

## Approach

Причина бага установлена исследованием: `areaVisualizer` (белая рамка, нативный объект `DragTool`) скрывается при обычном MouseUp **только** в `DragTool.OnLeftClickUp` (`DragTool.cs:243`), но эта строка недостижима, когда `GetMode()` возвращает `Brush` — ранний return на `DragTool.cs:239-242`. Когда шифт отпущен до MouseUp, `GetMode()` → Brush (префикс мода не переключает в Box без шифта), поэтому рамка остаётся активной; будучи child-ом transform инструмента (`DragTool.cs:103`), она «едет» за курсором через `BuildTool.UpdateVis` (`BuildTool.cs:198`).

Исправление Stage 1 (случай 1, выполнено): в существующем `DragTool_OnLeftClickUp__Patch.Postfix` (`BestBuildDryWall/Mod.cs`) после оригинала добавить сброс рамки — если `areaVisualizer` инструмента активен, сделать `SetActive(false)`. Не мешает нормальному пути с зажатым шифтом (там оригинал сам скрывает рамку на `:243`, постфикс no-op).

Исправление Stage 2 (случай 2, уточнение пользователя): рамка должна гаснуть в момент отпускания Shift в середине тяжки. Место — существующий `DragTool_OnMouseMove__Patch.Postfix` (`BestBuildDryWall/Mod.cs`), где при активной сессии и `!ShiftHeld()` уже вызывается `End("shift released")`: там же скрывать рамку (null-safe `SetActive(false)`). Чтобы не сломать поток «отпустил Shift → снова нажал без движения мыши → тяну», при зажатом Shift во время тяжки рамку, наоборот, показывать (`SetActive(true)`) — гейт по «тянет прямо сейчас» (LMB зажат / `dragging`), чтобы при обычном ховере без клика рамка не появлялась. Детали гейтов (поля `dragging`, доступность `RemoveCurrentAreaText`) определяются на этапе реализации; при скрытии рамки чистить и её текст «W x H / N tiles», если метод доступен (на mouse-up оригинал его чистит сам на `:233`, в середине тяжки — нет).

## Constraints

- Стек: C# net48, Harmony (game's 0Harmony.dll v2), PLib 4.19.0; единственный авто-шаг проверки — `dotnet build ONI-mods.sln -c Debug`; приёмка — ручная в игре пользователем.
- Мод — один файл `BestBuildDryWall/Mod.cs`; все патчи — Harmony-классы внутри него.
- `areaVisualizer` у инструмента стены — заимствованный объект (preb wall-tool его не содержит); объект переживает сессию, разрушается никогда — скрывать только через `SetActive`.
- Ключевое ограничение задачи #2 (Fix #3): сессия призраков должна оставаться активной во время оригинального `OnLeftClickUp` (`End("mouse up")` — postfix, не prefix); не трогать.
- Не ломать: повторное нажатие шифта без движения мыши возобновляет Box-режим — после Stage 2 рамка в этот момент скрыта, поэтому постфикс при зажатом Shift во время тяжки должен рамку показывать (no-op в штатном пути, где она уже активна).
