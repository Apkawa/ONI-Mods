## Stage 2 — Tooltip size block (the patch)
- [x] Implement the full patch in `SizeInTooltip/Mod.cs` (programmatic `harmony.Patch` in `OnLoad`, same style as `BuildDoorOverWall/Mod.cs`): Harmony **prefix** on `HoverTextConfiguration.DrawInstructions(HoverTextScreen, HoverTextDrawer)`. Behavior: if `__instance.gameObject` carries a `DragTool` and `dragTool.Dragging == true` and the drag mode is Box/Line (not Brush) — before the mouse-button line: `drawer.NewLine()` + draw «РАЗМЕР:» + the size line. W/H/N are read from the same state the game uses — `areaVisualizerSpriteRenderer.size` (meters) rounded to cells exactly as `DragTool.OnMouseMove` does (private fields via reflection on the publicized assembly; every access null-guarded so the mod can never crash the game). The numeric line is formatted with the game's localized key `UI.TOOLS.TOOL_AREA_FMT` ("{0} x {1}\n{2} tiles") so it auto-localizes and always matches the in-rectangle label; the «РАЗМЕР:» header is hardcoded RU.
- [x] Build green: `NUGET_PACKAGES="$PWD/.cache/nuget/packages" NUGET_HTTP_CACHE_PATH="$PWD/.cache/nuget/http-cache" dotnet build ONI-mods.sln -c Debug`. (Verified by an independent build run: 0 errors, `SizeInTooltip` compiles with 0 warnings; fresh artifacts in `bin/` and `.tmp/build_mod_dir/SizeInTooltip_dev/`. Note: the literal CLI is blocked in the sandbox by the first-run sentinel write to `~/.dotnet`; the MSBuild-muxer equivalent ran with the same restore+build semantics, caches in `.cache/`.)

**Criterion:** build is green; the patch compiles against the publicized game types; the state read mirrors `DragTool.OnMouseMove` (same fields, same rounding) per `research.md` Q2.
**Commit:** `feat(size-in-tooltip): show selection size in drag-tool tooltips`
