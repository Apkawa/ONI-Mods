# 2026-09-18_replace-building-material: ReplaceBuildingMaterial

**Created:** 2026-09-18T13:45:00+03:00

## Scope

**Внутри:**
- Новый мод `ReplaceBuildingMaterial` для «обычных» зданий (buildings). Здания с собственной нативной семантикой замены (двери, фундаменты, лестницы, окна и т.п. — defs, у которых уже настроена нативная замена) **исключены** из scope.
- Мод позволяет разместить то же самое здание (тот же pref) поверх уже существующего здания того же pref — в **той же самой позиции** (без поворотов и сдвигов), но с другим материалом.
- После разрешения размещения срабатывает обычная логика игры (нативный механизм замены): по завершении строительства старое здание разбирается, его материалы возвращаются работнику (refund), новое строится с выбранным материалом. Мод этот механизм не reimplementирует — он только разрешает размещение.
- Если выбранный материал совпадает с текущим (медь на медь) — пропуск: размещение не разрешается, ничего не происходит.
- Работает и для многоклеточных зданий.

**Снаружи:**
- Стены, провода, трубы, фундаменты и прочие типы объектов (не здания).
- Замена материала другими способами (не через построение поверх).
- Повороты/сдвиги: размещение разрешено только при полном совпадении позиции.
- Любое изменение механики разбора/возврата материалов (это поведение игры).

## Approach

- Следовать паттерну `BuildDoorOverWall`: один `Mod.cs`, `Mod : UserMod2`, патчи подключаются программно через `harmony.Patch(...)` (включая приватные методы с `out string` параметрами — через reflection-хелпер).
- Ядро: **инжекция метаданных замены в `BuildingDef`** (postfix на `Assets.AddBuildingDef`) — `Replaceable = true`, `ReplacementLayer = ObjectLayer.ReplacementTile`, `ReplacementCandidateLayers = {ObjectLayer.Building}` (общий static), `ReplacementTags = {def.Tag}` (per-def, только свой pref), чтобы нативная машина замены игры (R3) рассматривала «здание поверх здания того же pref» как легальную замену.
- **Пакет патчей (подтверждён глубоким исследованием, D3.1/R10):**
  - postfix на `Assets.AddBuildingDef` — инъекция метаданных замены (D1) только в «обычные» defs (предикат D2);
  - **prefix на `BuildTool.TryBuild(int)`** — отклонение сдвинутых/повёрнутых drag-ов (чистый отказ, без записи в Grid); создание плана для единственного валидного случая (полное совпадение позиции) делает нативный fallback сам (R9-Q1 — area-aware переписывание `TryBuild`, как в `BuildDoorOverWall`, НЕ требуется: при полном совпадении anchor-клетка всегда занята кандидатом);
  - **обязательный prefix на `Constructable.FinishConstruction`** — нативное завершение сломано для N≥2 при полном совпадении (R9-Q2.4): реентри-бейл по `finished` + до-свип очистка slot-1 записей anchor-кандидата в не-anchor клетках (шаблон `BuildDoorOverWall` минус distinct-candidate ветку);
  - postfix на `IsValidReplaceLocation` (UX) — **двусторонний**: нативное тело чисто геометрическое (R10.1), не знает о материале, поэтому postfix должен и краснить полное совпадение с тем же материалом («занято», как без мода); patch на `IsValidPlaceLocation` не нужен.
- «Материал совпадает → пропуск» уже есть в нативном гейте (R3: `candidate.Def == def && selectedElements[0] == candidate element`); при совпадении материала размещение выглядит как «занято» — красная подсветка, как без мода, дубликат не создаётся.
- Если в момент размещения поверх идёт разбор (деконструкция) старого здания, принимаем нативное поведение: `Constructable.OnSpawn` отменяет текущий де-конструкт (R3) — мод его не меняет.
- UX: подсветка (hover tint) — двусторонний postfix на `IsValidReplaceLocation`: белая только для валидного случая (разный материал, полное совпадение), красная иначе (R10.1/R11).

## Constraints

- TFM **net48** везде; Harmony — игровая `0Harmony.dll` v2; PLib 4.19.0 через `UtilLibs` (ProjectReference, PLib пакуется в dll мода).
- Структура мода: папка с `<Name>.csproj` + `Mod.cs` (+ README/AGENTS), `<IsMod>true</IsMod>`, `IsPacked=true`; проект добавляется в `ONI-mods.sln` (строка `Project(...)` + 4 строки конфигураций, комменты в sln запрещены).
- Единственная автоматизированная проверка — `dotnet build`; приёмка пользователем вручную в игре.
- Логи — `PUtil.LogDebug/LogError` + `.F(...)`; имя мода в логах не повторять; verbose — под `#if DEBUG`.
- Игровой билд — Aquatic 731233; класс `Minimap` в этой версии отсутствует, всё размещение идёт через `BuildTool : DragTool`.
