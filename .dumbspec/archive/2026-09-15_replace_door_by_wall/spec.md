# 2026-09-15_replace_door_by_wall: доработки мода BuildDoorOverWall

**Created:** 2026-09-15T17:00:21+03:00

## Scope

В скоупе (две фичи, стиль существующего мода — Harmony-патчи, без собственного UI):

1. **Обратная замена: дверь → «стена»/плитка пола.** Позволить построить здание поверх уже установленной двери и разрушить её (материалы двери возвращаются рабочему, нативный механизм замены). Цель — **все «стеноподобные» backwall-постройки** (`ExteriorWall` — в игре «гипсокартон», `GlassExteriorWall` (DLC5), `ThermalBlock` **и** все плитки-«клетки»: `Tile` (Клетка), `MetalTile` (Металлическая клетка), `InsulationTile` (Теплоизолированная Плитка) и прочие foundation-плитки игры — добавлено по уточнению пользователя, 2026-09-15: его «стены» — это на самом деле плитки пола, «фоновые стены» — гипсокартон). Дверь 1×2, здание 1×1: ставится на **одну** ячейку двери, **вторая ячейка остаётся пустой** (нативное поведение, согласовано). Доступно для **всех 6 видов** дверей.
2. **Замена двери на дверь другого типа.** Позволить построить дверь *другого вида* (другой PrefabID) поверх уже установленной двери. Набор видов: `Door`, `WoodenDoor`, `ManualPressureDoor`, `InsulatedDoor`, `PressureDoor`, `BunkerDoor`. **Пропуск:** тот же PrefabID — независимо от элемента/материала (например, дверь из железной руды → дверь из золотой руды) — тема для другого мода; «пропуск» = ванильное поведение «место занято». **POI/запечатанные (Unsealable) двери — не кандидаты** на замену.

Не в скоупе:
- Замена двери того же вида с другим элементом (отдельный мод).
- Sandbox / instant build — текущий мод там не работает, новые фичи наследуют это ограничение.
- POI/запечатанные (Unsealable) двери как кандидаты на замену.

## Approach

Следуем архитектуре существующего мода (единый `Mod.cs`, программные postfix-патчи в `OnLoad`, без UI). Реализовано (Stage 1, код в `Mod.cs`):

1. **Метаданные замены через патч `Assets.AddBuildingDef`:** у door- и wall-like defs — общие живые списки `SharedReplacementTags` ({FloorTiles, Backwall, Ladders} + тег каждого строимого дверного PrefabID) и `SharedReplacementCandidateLayers` {FoundationTile, Backwall, Building}; у дверей `Replaceable = true`. **Stage 1.5: та же обработка для tile-like defs** (`IsTileDef`: `BuildLocationRule.Tile` + `TileLayer == FoundationTile`).
2. **Расширенные гейты:** `IsReplacementPlacementPossible` (door || wall-like || tile-like, area-aware поиск кандидата `TryFindReplacementCandidate`, occupancy, 6-арг. `IsValidPlaceLocation(replace_tile:true)`).
3. **Расширенные патчи:** 6-арг. `IsValidPlaceLocation`-flip (wall-like + `HasDoor` + кандидат + свободный replacement-слот), `BuildTool.TryBuild` (door-defs; wall/tile идут нативно), косметические 4-арг. `IsValidPlaceLocation` и `IsValidReplaceLocation`.
4. **Фича 2 — правило пропусков:** нативный `BuildTool.TryBuild` пропускает замену только при совпадении `def` И элемента; мод дополнительно пропускает *любой* тот же PrefabID (независимо от элемента) — «пропускаем» = ванильное поведение «место занято».
5. **Размерность:** дверь 1×2, здание 1×1 — одна панель на одну ячейку, вторая ячейка двери остаётся пустой (согласовано с пользователем).

**Обнаруженные при тестировании пользователя баги (Stage 1, фикс в Stage 1.5):**

- **Bug A** (wall-over-door: план ставится, но при строительстве «Место не подходит для стройки»): повторная проверка при начале стройки `Constructable.cs:747` → ядро `IsValidBuildLocation(GameObject, int, Orientation, bool, out string)` (BuildingDef.cs:1220) — в ветке `NotInTiles` блок `!Grid.HasDoor[cell]` срабатывает **даже при `replace_tile == true`**. Фикс: postfix на ядро, переворачивающий `false → true`, когда нативный результат false и общий гейт замены проходит (кандидат-дверь есть, replacement-слот свободен). Дополнительно: occupancy-проверка гейта должна **игнорировать `source_go`** — сам план стоит в `Grid.Objects[cell, def.ReplacementLayer]` (`Constructable.MarkArea`), иначе гейт видит план как «слот занят» и flip не сработает. Для tile-direction flip НЕ нужен (Tile-ветка ядра без HasDoor — проходит нативно).
- **Bug B** (door-over-door: краш `ArgumentOutOfRangeException` при завершении стройки): старый 1×2-дверной GO зарегистрирован в `ObjectLayers[Building]` на **обеих** своих ячейках; якорная ветка `OnCompleteWork` разрушает его (отложенный `DestroySelf`) и сразу возвращает материалы, а `FinishConstruction` (вызывается из отложенного callback разрушения) просматривает остальные ячейки и находит **тот же умирающий** GO → второй `SpawnItemsFromConstruction` → чтение `PrimaryElement.Temperature` уже вычищенной структуры → краш. Фикс: **prefix** на `Constructable.FinishConstruction` — до нативного sweep дублирующий кандидат (тот же GO, что обработан в якорной ветке) вычищается из `Grid.Objects[ячейка, слой]` по слоям `ReplacementCandidateLayers`, sweep его не находит. Без состояния, не трогает preview-пути и разные кандидаты.

**Баги второго раунда тестирования пользователя (Stage 1.5/2, фикс в Stage 2.5):**

- **Bug C** (гипсокартон только на верхней ячейке двери: дверь не демонтируется, «превращается в натуральные блоки» из того же материала; гипсокартон при этом строится; с клеткой/тайлом проблемы нет): root cause (R8) — нативный `SimCellOccupier.DestroySelf` для кандидата 1×2 двери вешает **по одному callback-handle на каждую ячейку** → отложенная замена элемента освобождает **оба** callback → `FinishConstruction` выполняется **дважды** → второй раз `Def.Build` создаёт **призрачный дубликат** стены в той же ячейке (первый GO живёт без грид-слота). Возврат материалов двери — нативный путь «предметы на пол, рабочий подбирает» (код идентичен для стены и тайла; видимая разница стена/тайл — через `WasReplaced()`/стали-грид-записи у тайла). Фикс (Stage 2.5): сделать второй запуск `FinishConstruction` no-op (без второго `Def.Build`) — защита от повторного входа по состоянию завершения плана (отражение приватных полей `finished`/`unmarked` или статический ключ по GO плана с очисткой в конце первого запуска).
- **Bug D** (другая дверь с частичным перекрытием — новая повернута, перекрывает верхний/нижний тайл старой двери: старая демонтируется, новая не появляется, ресурсы пропадают): root cause (R9) — перекрытие в **неякорной** ячейке: в `OnCompleteWork` кандидата в якорной ячейке нет → прямой синхронный `FinishConstruction` → нативный sweep находит старую дверь в неякорной ячейке → `DestroySelf(null)` с **null-callback** → в ветке `doReplaceElement == false` — `NullReferenceException` (SimCellOccupier.cs:176) → стек обрывается: `SpawnItemsFromConstruction` (ресурсы) и `Def.Build` (новая дверь) не выполняются, план остаётся недоделанным; prefix мода в этом случае не срабатывает (уходит при `anchorCandidate == null`). Фикс (Stage 2.5): prefix `FinishConstruction` должен **сам** безопасно обрабатывать sweep-кандидатов (no-op callback без null + очистка грид-записей, чтобы нативный sweep ничего не нашёл) — устойчиво к **обеим** веткам `doReplaceElement` (сериализованное значение в prefab не проверимо локально).
- **Bug E** (ручной шлюз `ManualPressureDoor` / механизм. шлюз `PressureDoor` на клетках — красный тултип «Нужно построить на свободном участке»; на гипсокартоне — красный призрак + «Мешает задняя стена»; «двери всё равно ставятся»; у пневматической `Door` и деревянной `WoodenDoor` ошибок нет): root cause — **матрица door-defs** (R11, проверено по всем 6 конфигам): у `ManualPressureDoor`/`PressureDoor`/`InsulatedDoor`/`BunkerDoor` — `IsFoundation = true`, **`TileLayer = FoundationTile`**; у `Door`/`WoodenDoor` — `TileLayer = NumLayers`. Расцветка пользователя **точно совпадает** с этим разделением. Нативный hover-вызов (4-арг. `IsValidPlaceLocation`, `replace_tile: false`) не ищет кандидатов → для defs с `TileLayer = FoundationTile` срабатывает проверка занятости tile-слоя `IsAreaClear:608-613` → «Нужно построить на свободном участке» (над тайлом), а над гипсокартоном — BACK_WALL-проверка `IsValidTileLocation:810-813` (`!replacement_tile`) → «Мешает задняя стена». У `Door`/`WoodenDoor` нативный вызов тоже ложится, но flip гейта мода его скрывает (белый призрак). **Root cause РЕШЁН** (R12, data-driven через E-1-инструментацию + Player.log): `IsTileDef(airlock) == true` (`BuildLocationRule.Tile` + `TileLayer = FoundationTile`) → обратная (Stage 3/4) проверка в `TryFindReplacementCandidate` («wall/tile def → кандидат должен быть дверью») отвергала тайл/гипсокартон-кандидаты именно для четырёх шлюз-дверей — гейт ложился на **первом** шаге («no replacement candidate in the door area» в логе). У `Door`/`WoodenDoor` (`TileLayer = NumLayers`) проверка не срабатывает — полное совпадение с наблюдением. **Фикс (E-3, Stage 2.5):** исключить door-defs из этой проверки (`!IsDoorDef(def) && ...`); для non-door wall/tile defs поведение не меняется. Дальнейшие шаги гейта для шлюза проходят нативно: 6-арг. `replace_tile: true` — `IsAreaClear:608` пропускает tile-блок при найденном кандидате, `IsValidTileLocation:810` обходит backwall-блок при `replacement_tile == true` (поэтому двери и ставились ванильным путём — TryBuild postfix уходит при уже существующем плане). E-2: flip-guard сужен до `IsWallDef || IsTileDef` (в door-only TryBuild postfix без эффекта). Осталось: повторный прогон пользователя (ожидаемо — белый призрак, без красного текста, установка как раньше). Дополнительно (R11): flip-блок Stage 1.5 (Mod.cs:963-976) с условием `TileLayer != NumLayers` **несанкционированно срабатывает и для шлюзов** при drop (переворот ориентации + смещение якоря плана) — убрать для door-defs.

## Constraints

- Мод = один файл `BuildDoorOverWall/Mod.cs`: `UserMod2.OnLoad` + программные postfix/prefix-патчи + хелперы (`FindMethod`, `IsDoorDef`, `IsWallDef`, `IsTileDef`, `IsReplacementPlacementPossible`, `TryFindReplacementCandidate`). PLib используется только для логов (через `UtilLibs`).
- **Игра (установленная сборка, dll в `~/ONI/dlls`):** 6 видов строимых дверей — `Door`, `WoodenDoor` (DLC2), `ManualPressureDoor`, `InsulatedDoor`, `PressureDoor`, `BunkerDoor` (4×1); «материал» = выбранный элемент (у `Door` — ALL_METALS).
- **В этой сборке НЕТ классической «Стены» (Wall) и BunkerWall.** Стеноподобные постройки: `ExteriorWall` («Drywall»/гипсокартон), `GlassExteriorWall` (DLC5), `ThermalBlock`; плитки-«клетки»: `Tile`, `MetalTile`, `InsulationTile` (+ прочие foundation-плитки через `CreateFoundationTileDef`).
- `WoodenDoor` и `InsulatedDoor` имеют `Replaceable = false` — мод включает флаг.
- Поставленная дверь живёт в `ObjectLayer.Building`, ставит `Grid.HasDoor[cell]` на обе ячейки; стены — `ObjectLayer.Backwall` + `NotInTiles`; плитки — `TileLayer = FoundationTile`, план замены стоит в `ReplacementTile`/`ReplacementBackwall`-слоте.
- Жёсткий блок: `IsValidBuildLocation`/`IsAreaClear` (NotInTiles) запрещают ставить backwall на ячейку двери **даже в replace-режиме** — обходится flip-патчами (Stage 1.5).
- Нативный механизм замены при construction: `Constructable.IsReplacementTile` → `OnCompleteWork` (якорь) + `FinishConstruction` (остальные ячейки multi-cell) разрушают кандидата, `Deconstructable.SpawnItemsFromConstruction` возвращает элементы, `Trigger(1606648047, ReplaceCallbackParameters)`; `DeleteObject` = отложенный `Object.Destroy` (грид-записи не чистит — источник Bug B).
- Сборка: net48, `0Harmony` из игры, PLib 4.19.0 через `UtilLibs` (`IsPacked`), `dotnet build ONI-mods.sln`; приёмка — только ручные прогонки игрока (тестов нет).
- Дерево декомпиляции `lib_sources/Assembly-CSharp` частичное (`MainConfigs` отсутствует), актуальность проверена против dll.
